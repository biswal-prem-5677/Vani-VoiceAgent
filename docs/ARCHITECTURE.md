# VaniVoice AI — Technical Architecture

## 1. End-to-End Voice Turn Pipeline

```text
Browser (LiveVoiceCall.tsx + App.tsx in-memory Bearer token)
  ├─ Web Speech API SpeechRecognition (or typed text / 1-click prompt)
  ├─ Ref-backed state sync (turnsRef, callMemoryRef, activeLanguageRef, isMutedRef, inFlightTurnRef)
  ├─ AbortController + strict single in-flight lock + idempotencyKey
  └─ POST /api/turn ──▶ Express Server (server.ts) + X-Trace-Id propagation
                          ├─ 1. Auth & Rate Limiters (Bearer verifySessionToken, 60 turns/min/IP)
                          ├─ 2. Strict Tenant Lookup (404 TENANT_NOT_FOUND) + __turn__ Idempotency Cache
                          ├─ 3. Language Detection (or / hi / hinglish / bn / en)
                          ├─ 4. Safety Router (Tenant-Aware)
                          │     ├─ Emergency symptoms -> 112 advice + durable critical ticket (30d expiry)
                          │     └─ Explicit human transfer -> durable high ticket in handoff_tickets
                          ├─ 5. Entity Extraction + Cross-Lingual RAG Search (searchKnowledgeBase)
                          ├─ 6. Server AI Generation (or explicit Offline Demo Mode)
                          │     ├─ Gemini multi-turn history + bounded 4000-char KB digest
                          │     ├─ Per-tenant tool allowlist verification
                          │     └─ Exact paramsHash + immutable actionId confirmation gate
                          │           └─ Clinic SQLite appointments ledger & double-booking guard
                          └─ 7. JSON Response (real ragMs / modelResponseMs / totalTurnaroundMs) -> TTS + Transcript
```

## 2. Authentication, Firebase OIDC, Immediate Revocation & RBAC (`src/utils/auth.ts`, `src/lib/firebase-admin.ts`)

- **Fail-Fast Production Startup**: `npm start` (`node server.ts`) runs in production mode unless `--dev` or `NODE_ENV=development` is active. `verifyProductionSecurityConfig()` blocks production startup if `SESSION_SECRET` is missing or `< 32` chars, or if no admin protection mechanism (`ADMIN_PASSCODE`, `ADMIN_BOOTSTRAP_TOKEN`, or an existing SQLite `super_admin`) is present.
- **Google OIDC via Firebase Auth**: `POST /api/auth/firebase` verifies Firebase ID tokens via `firebase-admin/auth` (`verifyIdToken`), enforces `email_verified === true`, auto-provisions the primary `ADMIN_EMAIL` (default `priyabratabiswal567@gmail.com`) or existing SQLite users, and rejects revoked accounts with `401`/`403`.
- **Immediate DB Re-Verification on Every Request**: For registered non-passcode accounts, `resolveAuthUser` queries SQLite `users` on every protected request so role changes (`PATCH /api/auth/users/:id/role`) and revocations (`POST /api/auth/users/:id/revoke`) take effect immediately without waiting for token TTL expiry.
- **Protected Bootstrap & No Token Persistence**: If `ADMIN_BOOTSTRAP_TOKEN` is set, `POST /api/auth/bootstrap` requires constant-time token verification. Bearer tokens reside strictly in React memory (`App.tsx`); passwords use per-user 16-byte salts + `crypto.scryptSync`.

## 3. Exact Confirmation Matching, Appointments Ledger & External Integrations (`server.ts`, `src/utils/externalIntegration.ts`)

1. **Canonical Parameter Hashing (`canonicalizeToolParams`)**:
   - Strips confirmation control keys (`confirmed`, `actionId`), normalizes whitespace/casing, and hashes `{ toolName, params }` with SHA-256 into `paramsHash`.
   - Confirming with mismatched/tampered parameters fails safely back to a fresh confirmation prompt rather than committing altered arguments; confirmed rows transition atomically (`WHERE id = ? AND status = 'pending'`) and store `result_json` for idempotent replay.
2. **SQLite Clinic Appointments Ledger & `.ics` Calendar Invites**:
   - `check_slot_availability` dynamically filters confirmed SQLite bookings; `book_appointment` prevents double-booking of `(tenant_id, doctor, slot)` (`90`-day expiry).
   - Confirmed appointments expose `GET /api/appointments/:id/calendar.ics` generated by `buildCalendarIcs()` (RFC-5545 `VEVENT` with `DTSTART`/`DTEND`/`UID`).
3. **SSRF-Protected Signed Outbound Webhooks (`integration_deliveries`)**:
   - `book_appointment` confirm (`appointment.confirmed`), admin cancellation (`appointment.cancelled`), and safety/human handoffs (`handoff.created`) enqueue durable records into `integration_deliveries` and dispatch HTTP POST payloads signed with HMAC-SHA256 (`X-VaniVoice-Signature`, `t=...,v1=...`).
   - Outbound URLs pass `validateOutboundWebhookUrl()` (blocking loopback, link-local metadata `169.254.169.254`, and RFC1918 private IPs unless `ALLOW_LOCAL_WEBHOOKS=true` in test/dev). Failed deliveries use bounded exponential backoff (`3` attempts) and can be manually replayed via `POST /api/integrations/:id/retry`.

## 4. Speech Recognition & Synthesis Lifecycle (`LiveVoiceCall.tsx`, `src/utils/speechRecognition.ts`, `src/utils/speechSynthesis.ts`)

- Synchronous ref + React state updaters prevent stale closures in long-lived Web Speech `onstart`, `onresult`, `onerror`, and `onend` listeners.
- `src/utils/speechRecognition.ts` classifies fatal (`not-allowed`, `service-not-allowed`) vs. benign (`no-speech`, `aborted`) errors, enforces bounded exponential backoff (`150ms`–`3000ms`), and cleans up timers on unmount.

## 5. Persistence, Firestore Rules, Audit Trail & Operational Metrics (`server.ts`, `firestore.rules`, `src/utils/operationalMetrics.ts`)

- **Cloud Firestore (`firebase-blueprint.json` + `firestore.rules`)**: Client SDK (`src/lib/firestoreStore.ts`) syncs authenticated user profiles, tenant configs, session logs, handoffs, appointments, webhook deliveries, and support tickets under Eight-Pillar security rules validated by `npx eslint firestore.rules` and `firestore.rules.test.ts`.
- **10 SQLite Tables (`vanivoice.db`)**: `tenants`, `call_logs`, `consent_records`, `support_tickets`, `handoff_tickets`, `pending_actions`, `users`, `appointments`, `integration_deliveries`, and `audit_logs`.
- **Automatic Expiry Worker**: Startup sweep plus a 15-minute `setInterval(...).unref()` deletes expired `call_logs`, `handoff_tickets` (30d), `integration_deliveries` (30d), `support_tickets` (90d), `appointments` (90d), and stale pending confirmations (24h).
- **Operational Outcomes (`GET /api/metrics/operational`)**: `computeOperationalMetrics()` aggregates call volume, containment rate, escalation rate, tool confirmation rate, webhook delivery success, median/P95 latency, and language distribution.
- **Node 22 Native ESM (`node server.ts`)**: All server imports use explicit `.ts`/`.json` (`with { type: 'json' }`) extensions and `import type`, with Vite loaded lazily only when `--dev` or `NODE_ENV=development` is active.
